# دليل ربط قناة داري بتطبيق مُثبَت

هذا الدليل يشرح بنية الربط الحالية، إعداد القناة، دورة الاتصال والرسائل والملفات، الأمن، التشغيل، ونقاط التحقق. التكامل الحالي مكتوب بـ Flutter/Dart ويعمل بوضع **الزائر المجهول**.

## 1. بيانات قناة التطوير

```json
{
  "baseUrl": "https://devdarai.prideidea.com",
  "cId": "appchat_da989a3626a7",
  "appId": "app_1cf1c3bc",
  "platform": "appchat",
  "tokenUrl": "https://devdarai.prideidea.com/ws/token",
  "uploadUrl": "https://devdarai.prideidea.com/ws/upload",
  "webSocketUrl": "wss://devdarai.prideidea.com/ws/ws"
}
```

هذه القيم تخص قناة التطوير الحالية. `cId` و`appId` معرفات تعريفية وليستا أسرار مصادقة. لا تستبدلها بقيم الإنتاج إلا بالقيم التي يصدرها فريق داري لبيئة الإنتاج.

## 2. ملفات التكامل

| الملف | المسؤولية |
|---|---|
| `lib/features/support/data/darai_chat_client.dart` | إصدار التذكرة، تخزين مفتاح الزائر الآمن، اتصال WebSocket، الرسائل، إعادة الاتصال، ورفع الملفات. |
| `lib/features/support/presentation/darai_chat_screen.dart` | واجهة الدردشة القابلة لإعادة الاستخدام، حالة الاتصال، الرسائل، وإرفاق الصور. |
| `lib/app/router/app_routes.dart` | مسار الشاشة باسم `/darai-chat`. |
| `lib/features/local_ledger/local_ledger_screen.dart` | زر فتح الدردشة من شريط الدفتر. |
| `pubspec.yaml` | الاعتماديات المطلوبة؛ `flutter_secure_storage` و`http` و`http_parser` و`image_picker` مستخدمة في التنفيذ الحالي. |

## 3. الإعداد

الاعتماديات وصلاحية الإنترنت موجودة مسبقًا في المشروع:

```yaml
dependencies:
  flutter_secure_storage: ^11.1.1
  http: ^1.2.2
  http_parser: ^4.1.2
  image_picker: ^1.2.3
```

صلاحية Android المطلوبة في `android/app/src/main/AndroidManifest.xml`:

```xml
<uses-permission android:name="android.permission.INTERNET" />
```

بعد تعديل الاعتماديات:

```powershell
cd mobile
flutter pub get
flutter analyze

```

لا حاجة لإضافة صلاحية تخزين عامة لاختيار صورة عبر منتقي النظام الحديث. يتولى `image_picker` فتح منتقي الصور وإرجاع الملف المختار.

## 4. فتح واجهة الدردشة

### من مسار التطبيق

```dart
Navigator.pushNamed(context, AppRoutes.daraiChat);
```

### فتح الشاشة مباشرة

```dart
Navigator.of(context).push(
  MaterialPageRoute<void>(
    builder: (_) => const DaraiChatScreen(),
  ),
);
```

تستخدم الشاشة افتراضيًا إعداد التطوير، ويمكن تخصيص اسم الشاشة ونص الترحيب وإخفاء زر المرفق:

```dart
const DaraiChatScreen(
  title: 'محادثة خدمة العملاء',
  welcomeTitle: 'مرحبًا بك',
  welcomeMessage: 'اكتب استفسارك وسيتواصل معك فريقنا.',
  allowImageAttachments: true,
);
```

### إعداد قناة مختلفة

مرّر الإعدادات بدل تعديل عميل الشبكة:

```dart
const productionChat = DaraiChatConfig(
  baseUrl: 'https://darai.example.com',
  cId: 'CHANNEL_ID_FROM_DARAI',
  appId: 'APP_ID_FROM_DARAI',
  platform: 'appchat',
  tokenPath: '/ws/token',
  uploadPath: '/ws/upload',
  webSocketPath: '/ws/ws',
);

Navigator.of(context).push(
  MaterialPageRoute<void>(
    builder: (_) => const DaraiChatScreen(config: productionChat),
  ),
);
```

استخدم النطاق الرسمي وبيانات القناة التي يزودك بها فريق داري. يرفض العميل عنوانًا لا يستخدم HTTPS، ويحوّل اتصال WebSocket تلقائيًا إلى WSS.

## 5. تسلسل الاتصال

1. تنشئ الشاشة `DaraiChatClient` وتستدعي `connect()`.
2. يقرأ العميل `visitor_key` الخاص بالقناة من `FlutterSecureStorage`، إن وُجد.
3. يرسل طلب JSON إلى `POST /ws/token`:

   ```json
   {
     "cId": "appchat_da989a3626a7",
     "platform": "appchat",
     "visitor_key": "يُرسل فقط عند توفر مفتاح محفوظ"
   }
   ```

   يحذف الحقل `visitor_key` من الطلب الأول إذا لم يكن محفوظًا.

4. يتحقق العميل من أن `app_id` في الاستجابة يطابق `appId` المهيأ، ويحفظ `visitorKey` المستلمة بأمان.
5. يحتفظ بـ `token` في الذاكرة فقط، ثم يفتح WebSocket باستخدام `senderId` و`wsTicket`:

   ```text
   wss://<host>/ws/ws?v=1&platform=appchat&app_id=<appId>&sender_id=<senderId>&ticket=<wsTicket>
   ```

6. عند انقطاع الاتصال، يعيد العميل المحاولة بتأخير تصاعدي يصل إلى 30 ثانية. يمكن للمستخدم طلب إعادة الاتصال من الواجهة.
7. يرسل العميل `ping` دوريًا، ويضبط WebSocket لإرسال ping على مستوى النقل.

يتحقق العميل من الاستجابة والأخطاء صراحةً؛ لا يعتبر فشل الخادم اتصالًا ناجحًا.

## 6. دورة الرسائل

### إرسال نص

```dart
final messageId = client.sendText('مرحبًا');
```

ينشئ العميل معرّفًا عشوائيًا آمنًا، ويحفظ الرسالة المعلقة في الذاكرة قبل الإرسال:

```json
{
  "event": "message.send",
  "id": "<client-message-id>",
  "payload": {
    "type": "text",
    "text": "مرحبًا"
  }
}
```

### الإقرارات والأخطاء

- `message.ack`: أُقرت الرسالة؛ يجب أن يطابق `id` معرّف الإرسال.
- `system.error`: افحص `retryable`. أعد المحاولة فقط عندما تكون `true` وباستخدام معرّف الرسالة الأصلي.
- `message.new`: رسالة واردة؛ تستخدم الواجهة `payload.message_id` لمنع التكرار.
- `connection.ready` و`connection.error`: تحديث حالة الاتصال في الواجهة.

عند وصول رسالة واردة، يرسل العميل `message.delivered`. وتستدعي الواجهة `markRead(messageId)` بعد عرضها.

```dart
client.markRead(replyMessageId);
client.retry(originalMessageId);
```

الرسائل المعلقة محفوظة في الذاكرة فقط؛ إغلاق التطبيق أو إنهاء العملية يفقدها. يتطلب ضمان عدم فقد الرسائل قاعدة بيانات محلية دائمة وحفظ **المعرّف الأصلي نفسه** قبل الإرسال. كما أن جلب سجل المحادثة بعد إعادة فتح الشاشة غير مطبق حاليًا ويتطلب API مخصصًا من داري.

## 7. رفع الصور

يستخدم الرفع:

```text
POST /ws/upload
Authorization: Bearer <access-token>
Content-Type: multipart/form-data
```

حقول النموذج:

| الحقل | القيمة |
|---|---|
| `type` | الفئة العامة `image`، وليست قيمة MIME. |
| `file` | محتوى الملف واسمه الأصلي مع ترويسة MIME الصحيحة. |

الصيغ التي تدعمها الواجهة الحالية:

| الامتداد | MIME |
|---|---|
| `.jpg`، `.jpeg` | `image/jpeg` |
| `.png` | `image/png` |
| `.webp` | `image/webp` |

مثال شكل الطلب:

```text
type=image
file=<photo.png; Content-Type: image/png>
```

التمييز مهم: أرسل الخادم `400 Invalid media type` عندما أُرسل MIME مكان الفئة، وأرسل `415 Unsupported file type` عندما لم يطابق نوع الملف المعلن محتواه/نوعه. لذلك يجب عدم وضع `image/png` في حقل `type`: القيمة هناك `image`، و`image/png` في ترويسة جزء الملف.

بعد نجاح الرفع، يتوقع العميل JSON يحوي `upload_token`. يرسل هذا الرمز في رسالة WebSocket، ولا يرسل بايتات الملف عبر WebSocket:

```json
{
  "event": "message.send",
  "id": "<client-message-id>",
  "payload": {
    "type": "image",
    "upload_token": "<short-lived-upload-token>"
  }
}
```

رمز الرفع مؤقت؛ أعد رفع الملف إذا انتهت صلاحيته. لا تعرض رابطًا أو رمزًا للمستخدم على أنه رسالة مرسلة قبل إقرار `message.ack`.

## 8. الهوية والحماية

### الوضع الحالي

التطبيق متصل كزائر مجهول، ويستعيد هوية الزائر عبر `visitor_key` المخزّن باستخدام `flutter_secure_storage`. هذا المفتاح يميّز جلسة الزائر لدى القناة، **ولا يثبت هوية حساب مُثبَت**.

### ربط حساب مُسجّل (غير مفعّل بعد)

إذا تطلب المنتج إسناد المحادثة إلى حساب مستخدم:

1. اطلب من فريق داري تفعيل إعداد هوية القناة وتوثيق عقد التحقق.
2. بعد مصادقة المستخدم في مُثبَت، يطلب التطبيق رمز هوية قصير العمر من خادم مُثبَت الموثوق.
3. يوقع الخادم الرمز، لا تطبيق Flutter. إذا أكد فريق داري استخدام JWT/HS256، يجب أن يحتوي `sub` على معرّف داخلي ثابت وأن يكون `exp` قصيرًا (لا يتجاوز 15 دقيقة بحسب العقد المتفق عليه).
4. يرسل العميل الرمز إلى `/ws/token` في `identity_token` بعد إضافة الدعم والاختبار في العميل.
5. يحفظ سر التوقيع في أسرار الخادم فقط. لا تضعه في Dart، أو `--dart-define`، أو ملفات `.env` التي تدخل التطبيق.
6. عند تبديل الحساب أو تسجيل الخروج: أوقف عميل الحساب السابق، أفرغ الرسائل المعروضة والمعلقة، ولا تعاود استخدام هوية الحساب السابق.

عميل المشروع الحالي لا يرسل `identity_token`؛ لا تفعّل وضع الحسابات قبل إضافة تدفق موثق واختباره مع فريق داري.

### ضوابط عامة

- استخدم HTTPS/WSS في جميع البيئات المنشورة.
- لا تسجل `token` أو `wsTicket` أو `visitor_key` أو `upload_token` أو محتوى الرسائل في السجلات.
- رموز الاتصال والرفع قصيرة العمر وتبقى في الذاكرة عند عدم الحاجة للتخزين.
- معرفات القناة ليست بديلًا عن المصادقة، ولا تعتبرها أسرارًا.
- تحقق من حجم الملف وأنواعه في الخادم أيضًا؛ تحقق العميل وحده لا يحمي API.
- لا تقبل روابط Origin أو CORS كوسيلة لإثبات هوية تطبيق Android/iOS.

## 9. إغلاق الجلسة وتبديل الحساب

عند إزالة الشاشة، تستدعي `dispose()` لإيقاف timers، وإغلاق HTTP وWebSocket، وإفراغ قائمة الرسائل المعلقة. إذا أصبح هناك ربط بحسابات، يجب إنشاء عميل جديد لكل جلسة حساب؛ لا تعِد استعمال العميل نفسه عبر تبديل الحساب.

## 10. الفشل والاستكشاف

| العرض | نقاط التحقق |
|---|---|
| مهلة عند الاتصال | اتصال الجهاز بالإنترنت، DNS/TLS للنطاق، توفر `/ws/token`، ثم مصافحة WSS. تعرض الواجهة المرحلة التي فشل عندها الاتصال. |
| `app_id mismatch` | طابق `appId` مع `app_id` الصادر من قناة البيئة نفسها. |
| `400 Invalid media type` | يجب أن يكون حقل النموذج `type=image`، لا `image/png`. |
| `415 Unsupported file type` | افحص الامتداد الفعلي و`Content-Type` لجزء `file`، واختر JPEG أو PNG أو WebP. |
| `401` أو `403` عند الرفع | استخدم Bearer token جديدًا صادرًا من `/ws/token`، وتحقق من ربط الرمز بالقناة والجلسة. |
| فشل `message.send` بعد نجاح الرفع | افحص `upload_token`، فئته، مدة صلاحيته، ونوع `payload.type`. أعد الرفع إذا انتهت الصلاحية. |
| تختفي الرسائل بعد إغلاق التطبيق | هذا متوقع حاليًا؛ التخزين الدائم وجلب سجل المحادثة غير مطبقين. |

لا تسجل الرمز لإرفاقه بتقرير المشكلة. يكفي تسجيل HTTP status ورمز الخطأ والمرحلة مع حذف أي بيانات اعتماد أو محتوى خاص.

## 11. خطة الاختبار قبل النشر

### آلي

```powershell
cd mobile
flutter analyze
flutter test
flutter build apk --release
```

أضف اختبارات وحدة للعميل باستخدام نقل HTTP/WebSocket قابل للحقن قبل اعتماد اختبار آلي لمهلات الشبكة، تجديد التذكرة، وإقرارات الرسائل.

### تكامل على جهاز فعلي

1. افتح الدردشة وتأكد من ظهور حالة الاتصال.
2. أرسل نصًا عربيًا وإنجليزيًا وتحقق من `message.ack` ثم الرد الوارد.
3. أرسل الصورة نفسها بصيغ JPEG وPNG وWebP، وتأكد من قبول `/ws/upload` وإرسال `upload_token`.
4. اختبر صيغة غير مدعومة وحجم ملف يتجاوز حد الخادم؛ يجب إظهار خطأ مفهوم دون رسالة نجاح.
5. افصل الشبكة وأعدها؛ تحقق من إعادة الاتصال وإرسال الرسائل المعلقة بمعرفاتها الأصلية.
6. اختبر العودة من الخلفية وإغلاق الشاشة أثناء الاتصال.
7. إذا أضيفت هوية الحساب: اختبر مستخدمين مختلفين وتسجيل الخروج/الدخول، وتأكد من عدم مشاركة المحادثات.
8. اختبر نسخة release؛ قد تختلف إعدادات الشبكة والتوقيع عن debug.

نجاح إصدار التذكرة ومصافحة WebSocket وحدهما لا يثبتان دورة محادثة كاملة. يجب التحقق من رفع الملف، وإقرار الرسالة، ووصول رد الوكيل على الجهاز وبيئة القناة المستهدفة.

## 12. حدود النسخة الحالية

- شاشة محادثة عربية RTL قابلة لإعادة الاستخدام، مع تهيئة القناة وتمرير عنوان ونص ترحيب وإتاحة المرفقات.
- اتصال زائر مجهول ورسائل نصية وصور مع إعادة اتصال تلقائية.
- لا يوجد دعم حالي لـ `identity_token` أو سجل محادثة دائم أو إشعارات خلفية.
- لا تعرض الشاشة الصور الواردة ضمن الرسالة؛ تعرض نص الرسالة/نوع المرفق فقط حتى يثبت عقد شكل payload وروابط الوسائط من داري.
- إعداد التطوير هو الافتراضي. مرّر إعداد القناة الصحيح عند فتح الشاشة في بيئة أخرى.
