# مواصفة المحاسبة المزدوجة — دفتر الديون

**الحالة:** مطبّقة فعلياً في الترحيلات `009`–`011` ومختبرة محلياً.

## الغرض

لم يعد النظام يسجل «ديناً» أو «دفعة» كرصد مستقل فقط. كل عملية تشغيلية تنشئ أيضاً قيداً يومياً متزناً: مجموع المدين دائماً يساوي مجموع الدائن. يبقى `ledger_entries` سجل العميل التشغيلي، وتبقى `journal_entries` و`journal_entry_lines` دفتر الأستاذ العام المحاسبي.

```mermaid
flowchart LR
  A[عملية في التطبيق] --> B[ledger_entries]
  B --> C[Trigger محاسبي ذري]
  C --> D[journal_entries]
  D --> E[journal_entry_lines]
  E --> F[ميزان المراجعة]
  E --> G[رصيد العميل: عليه / له]
```

## المعنى العملي للمدين والدائن

من منظور المحل:

| الحالة | المعنى | رصيد العميل |
|---|---|---|
| العميل **عليه مبلغ** | المحل له حق تحصيل من العميل | رصيد حساب العملاء مدين |
| العميل **له مبلغ** | للعميل رصيد دائن/دفعة مقدمة قابلة للاستخدام أو الاسترداد | رصيد حساب العملاء دائن |

تعرض الواجهة القيمتين منفصلتين من العرض `business_customer_account_positions`:

- `amount_customer_owes`: ما على العميل للمحل.
- `amount_business_owes_customer`: الرصيد الدائن للعميل، أي ما له لدى المحل.
- `receivable_signed_balance`: الرصيد المحاسبي الموقّع؛ موجب = مدين، سالب = دائن.

## دليل الحسابات الافتراضي لكل محل

ينشأ تلقائياً عند إنشاء المحل. يمكن لاحقاً توسيعه بحسابات فرعية دون تغيير الحسابات الضابطة.

| الرمز | الحساب | التصنيف | طبيعته | استخدامه |
|---:|---|---|---|---|
| 1000 | الصندوق/النقدية | أصل | مدين | قبض دفعات العملاء |
| 1100 | العملاء (الذمم المدينة) | أصل ضابط | مدين | ما على العميل أو رصيده الدائن |
| 3100 | حقوق ملكية رصيد افتتاحي | حقوق ملكية | دائن | الرصيد الافتتاحي للعميل |
| 4000 | إيرادات المبيعات | إيراد | دائن | تسجيل الدين/الفاتورة |
| 5100 | خصومات المبيعات | مصروف | مدين | خصم معتمد من حساب العميل |

إعدادات الربط محفوظة في `business_accounting_settings`. حساب العملاء `1100` حساب ضابط ولا يسمح بقيد يدوي مباشر؛ كل تغيير له يمر عبر عملية عميل موثقة.

## ترحيل العمليات إلى قيود يومية

| عملية التطبيق | القيد المحاسبي |
|---|---|
| رصيد افتتاحي 100 | مدين العملاء 100 / دائن حقوق ملكية الرصيد الافتتاحي 100 |
| دين أو فاتورة 100 | مدين العملاء 100 / دائن إيراد المبيعات 100 |
| دفعة 20 | مدين الصندوق 20 / دائن العملاء 20 |
| خصم معتمد 15 | مدين خصومات المبيعات 15 / دائن العملاء 15 |
| عكس عملية | يعكس طرفي القيد الأصلي بالقيمة نفسها |

### مثال عملي

فاتورة `200`، خصم `20`، ثم دفعة `230`:

| القيد | مدين | دائن |
|---|---:|---:|
| العملاء / المبيعات | العملاء 200 | المبيعات 200 |
| خصم مبيعات / العملاء | خصم المبيعات 20 | العملاء 20 |
| الصندوق / العملاء | الصندوق 230 | العملاء 230 |

رصيد العملاء = `200 - 20 - 230 = -50`، ولذلك يظهر للمستخدم: **عليه 0، له 50**.

## الجداول الجديدة

| الجدول | المسؤولية |
|---|---|
| `chart_of_accounts` | حسابات المحل: الرمز، الاسم، التصنيف، الطبيعة، الحساب الضابط، والسماح بالقيد اليدوي. |
| `business_accounting_settings` | ربط حساب العملاء، الصندوق، الإيراد، الخصم والافتتاحي بحسابات المحل. |
| `accounting_periods` | قفل فترة تاريخية حتى لا يقبل النظام قيوداً جديدة فيها. |
| `journal_entries` | رأس القيد: رقم متسلسل، المحل، مصدر العملية، التاريخ، الوصف والمستخدم الناشر. |
| `journal_entry_lines` | أطراف القيد: الحساب، بُعد العميل المحلي عند الحاجة، المدين والدائن. |
| `account_trial_balance` | ميزان مراجعة حي لكل حساب. |
| `business_customer_account_positions` | وضع العميل المحاسبي: عليه/له. |

## الضوابط المحاسبية

- كل قيد يومية يتطلب سطرين على الأقل، ويتحقق PostgreSQL مؤجلاً عند نهاية المعاملة أن إجمالي المدين = إجمالي الدائن.
- لا يسمح بتعديل أو حذف `journal_entries` أو `journal_entry_lines` بعد إنشائها.
- لا يقبل السطر حساباً لا يخص المحل أو حساباً غير نشط.
- لا يقبل حساب العملاء الضابط سطراً بلا `business_customer_id`.
- الخصم لا يتجاوز الرصيد المدين القائم للعميل، ويستلزم دور `owner` أو `admin` أو `accountant`.
- الدفع المسبق مسموح افتراضياً (`allow_customer_credit_balance=true`) لكي يدعم النظام «له مبلغ». يمكن إيقافه لكل محل من إعدادات المحاسبة.
- عندما تكون فترة محاسبية مقفلة، ترفض أي عملية يولد تاريخها قيداً داخل الفترة.
- قيد يدوي متزن متاح فقط للأدوار المحاسبية، ولا يسمح له بالكتابة في الحسابات الضابطة.

## واجهات العمليات الجديدة

| RPC | الاستخدام |
|---|---|
| `apply_customer_discount` | خصم معتمد من ذمة العميل؛ ينشئ قيد `discount` وقيداً يومياً. |
| `post_manual_journal` | قيد تسوية يدوي متزن في الحسابات غير الضابطة. |
| `close_accounting_period` | قفل فترة محاسبية لمنع التسجيل اللاحق فيها. |
| `account_trial_balance` | قراءة ميزان المراجعة للمحل. |
| `business_customer_account_positions` | قراءة «عليه/له» للعميل. |

## حماية وصلاحيات

- القوائم والقيود اليومية للطاقم النشط في المحل فقط؛ لا تظهر للعميل.
- لا توجد صلاحية كتابة مباشرة للجداول المحاسبية من التطبيق.
- العمليات تمر بدوال `security definer` التي تتحقق من الدور والمحل والفترة والحساب.
- العميل ما زال يرى كشفه التشغيلي بعد قبول الربط فقط؛ لا يكشف له دليل الحسابات أو الدفتر العام للمحل.

## التحقق المنفذ

يشمل `supabase/tests/database/003_double_entry_accounting.sql` التحقق من:

1. إنشاء دليل الحسابات تلقائياً للمحل.
2. قيد الدين والخصم والدفعة.
3. تساوي مجموع المدين والدائن لكل قيد.
4. تسجيل الخصم في الحساب 5100.
5. دعم رصيد دائن للعميل بقيمة 50.
6. قبول قيد تسوية يدوي متزن فقط.

المرحلة التالية المحاسبية، عند توسيع نطاق المنتج، تكون ضريبة القيمة المضافة، الصندوق/البنوك المتعددة، المصروفات والمشتريات والمخزون، وإقفال السنة إلى الأرباح المحتجزة. لا ينبغي إضافتها قبل تحديد المتطلبات القانونية والضريبية للدولة المستهدفة.
