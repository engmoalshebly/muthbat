# إصلاح تعليق جلب بيانات الزبون — 22 أكتوبر 2026

## الدليل والسبب

ظهر الخلل بعد بدء إصدار `0.2.1+3` على الهاتف الفعلي. سجل Android يُظهر بدء `BackgroundWorker` بالتزامن مع التطبيق، ثم تحذيرات متكررة بأن قاعدة البيانات مقفلة. ظهر أيضًا الخطأ الأصلي من SQLCipher:

```text
database is locked (code 5): retrycount exceeded
SELECT * FROM customer_outbox ORDER BY created_at,id
```

تبدأ شاشة الزبون بقراءة الملف المحلي والذاكرة المؤقتة وطابور الإرسال قبل قراءة الخادم. لذلك يعلق الجلب عندما ينتظر هذا المسار قاعدة البيانات، حتى لو كان اتصال الخادم متاحًا.

تستخدم نسخة `sqflite_sqlcipher 3.4.1` المثبتة معالج Android واحدًا ثابتًا لجميع اتصالات المحركات، بينما لكل محرك Flutter قفل معاملات Dart مستقل. عند فتح اتصالين للملف نفسه، يمكن أن تنتظر قراءة أحدهما معاملة الاتصال الآخر، ويكون إتمام تلك المعاملة خلف القراءة في طابور المعالج نفسه. تغيير `singleInstance` وحده لا يعزل المعاملات بين المحركات.

## التغيير

- إلغاء مهمة Android الدورية القديمة بالاسم المحدد، دون إلغاء مهام أخرى.
- الاحتفاظ بنقطة دخول المهمة القديمة، وجعلها تنتهي بنجاح على Android قبل فتح الحساب أو Supabase أو التخزين؛ يغطي ذلك مهمة بدأها النظام بالفعل بعد التحديث.
- تستمر المزامنة داخل محرك التطبيق عند الفتح والاستئناف وعودة الشبكة، وبالمؤقت الموجود في `AccountSyncHost`، مع استمرار الإرسال اليدوي.
- لم يتغير تنفيذ مهمة iOS.
- إضافة توقيت اكتمال قراءة الملخص والكشف أو نوع فشلها في السجل، دون أسماء أو مبالغ أو أرقام هواتف أو رموز جلسات.
- رفع الإصدار إلى `0.2.2+4` وبناؤه بإعدادات `run-cloud.ps1` نفسها (`APP_ENV=staging`).

## أثر التشغيل

لم تعد مهمة Android الدورية تفتح قاعدة الحساب عندما يكون التطبيق مغلقًا. تظل الطلبات المحلية محفوظة وتُرسل عند فتح التطبيق واستئنافه أو عودة الاتصال أثناء تشغيله. إشعارات FCM لا تعتمد على هذه المهمة. إعادة تفعيل الكتابة المجدولة من محرك ثانٍ تحتاج تنسيق معاملات مدعومًا بين المحركات؛ لا يكفي إنشاء اتصال إضافي أو زيادة مهلة الانتظار.

لا يتطلب هذا الإصلاح تعديل قاعدة Supabase أو حذف بيانات الهاتف أو تغيير بيئة الحساب.

- `flutter analyze --no-pub`: دون ملاحظات.
- مجموعة اختبارات Flutter الكاملة: **182 اختبارًا ناجحًا**.
- اختباران جديدان يتحققان من إلغاء مهمة Android بالاسم المحدد، وخروج أي استدعاء قديم قبل تهيئة حساب أو تخزين أو جلسة Supabase.
- اختبارات جلب الزبون وفتح قاعدة البيانات المتزامن ناجحة ضمن المجموعة الكاملة.
- بناء Release ناجح وتثبيت `0.2.2+4` على الهاتف بواسطة `adb install -r`. التوقيع مطابق للنسخة السابقة، ولم تُحذف البيانات.
- ملف التحديث: `releases/muthbat-0.2.2+4-cloud.apk`.
