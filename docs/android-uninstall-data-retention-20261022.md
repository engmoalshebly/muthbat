# الاحتفاظ ببيانات الدفتر عند حذف التطبيق

## الإعداد

أضيف `android:hasFragileUserData="true"` إلى تطبيق Android. يتيح ذلك لمثبت النظام عرض خيار الاحتفاظ ببيانات التطبيق عند إلغاء التثبيت. لا يستطيع التطبيق تخصيص نص نافذة النظام أو فرض الاحتفاظ رغم اختيار المستخدم حذف البيانات.

عند احتفاظ النظام ببيانات التطبيق ومفاتيح التشفير، تستطيع النسخة المعاد تثبيتها فتح دفتر SQLite الحالي؛ مسار بدء التشغيل الموجود يفتح الدفتر المحلي المحفوظ تلقائيًا. يلزم تطابق معرف الحزمة وتوقيعها وبيئة الدفتر، والتثبيت ضمن ملف المستخدم نفسه على الهاتف نفسه.

لا تُفعّل هذه الإضافة نسخ Android السحابي التلقائي؛ تبقى `allowBackup=false` واستثناءات النسخ كما هي. تصدير نسخة مشفرة إلى ملف خارج التطبيق متاح بالفعل من إعدادات الدفتر.

## حدود الاستعادة

- ظهور الخيار يعتمد على إصدار Android وواجهة إلغاء التثبيت المستخدمة وسياسات الجهاز.
- الدفتر مشفر بـ SQLCipher ومفتاحه محفوظ عبر Android Keystore. احتفاظ النظام بملفات قاعدة البيانات وحدها لا يكفي لفتحها إذا أزيل المفتاح.
- يوضح إصلاح AOSP أن بعض مسارات حذف مستخدم منفرد في الإصدارات الأقدم كانت تزيل مفاتيح Keystore حتى مع DELETE_KEEP_DATA؛ لذلك لا يصح ضمان الاستعادة لكل الأجهزة، خصوصًا مع تعدد ملفات المستخدمين. الهاتف المتصل وقت التنفيذ يعمل بـ API 31 وله ملف مستخدم إضافي.
- لا تُغير الإضافة المفاتيح ولا تقلل حماية البيانات لتجاوز اختلافات النظام. النسخة الاحتياطية المشفرة الخارجية هي مسار الاستعادة المستقل عن احتفاظ النظام بالمفاتيح.
- الاحتفاظ بالبيانات ليس استعادة لبيانات حُذفت سابقًا، ولا ينقل الدفتر إلى هاتف آخر.

## التحقق

- `flutter analyze --no-pub`: ناجح.
- اختبارات مخزن الدفتر وواجهته: 18 اختبارًا ناجحًا.
- بُني APK release ونجح فحص توقيعه. أكد `aapt2 dump xmltree` أن `hasFragileUserData=true` و`allowBackup=false` في manifest الفعلي داخل APK.
- ثُبت APK بتحديث `adb install -r --user 0` بنجاح وفتح التطبيق. بقيت بيانات المستخدمين 0 و150 مثبتة دون تغير معرف مجلد البيانات.
- لم يُلغَ تثبيت التطبيق الفعلي ولم تُمسح بياناته. اختبار إلغاء التثبيت وإعادة التثبيت مع بقاء دفتر مشفر لم يُنفذ على بيانات المستخدم؛ لا يُعد نجاح التحديث إثباتًا لنجاح الاستعادة بعد الحذف.
