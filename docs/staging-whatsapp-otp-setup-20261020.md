# تفعيل تحقق الهاتف عبر WhatsApp على staging

تم ربط وظيفة `send-whatsapp-otp` بمسار OpenWA:

`POST /api/sessions/{sessionId}/messages/send-text`

يرسل الخادم رمزًا عشوائيًا مؤقتًا إلى `رقم الدولة + الرقم@c.us`، ولا يصل مفتاح OpenWA إلى تطبيق الهاتف. يبقى التحقق الخادمي وتحديد المحاولات قائمين، ويُلغى التحدي إذا تعذر التسليم.

## الإعداد الآمن

مفتاح OpenWA الذي أُرسل في المحادثة يجب إلغاؤه وتدويره قبل الاختبار. لا تستخدمه ولا تضعه في Flutter أو Git.

1. انسخ `debt-ledger-supabase/deploy/staging/.env.example` إلى `.env` في المجلد نفسه. الملف مستثنى من Git.
2. أدخل في الملف مفتاح OpenWA الجديد ومعرّف جلسة WhatsApp الفعلية، وأبقِ `OPENWA_BASE_URL=https://notify.prideidea.com` و`WHATSAPP_OTP_ENABLED=true`.
3. تأكد أن مشروع staging يستخدم الجلسة نفسها وأنها بحالة جاهزة، ثم انشر عبر سكربت staging بعد تسجيل الدخول إلى Supabase CLI وضبط `SUPABASE_PROJECT_REF`.
4. شغّل التطبيق بإعداد `mobile/config/supabase.cloud.json` المحدّث، ثم ابدأ تسجيلًا تجريبيًا لرقم تملكه. لا ترسل رسالة اختبار يدوية؛ طلب التسجيل ينشئ رمزًا صالحًا لخمس دقائق ويرسله عبر المسار نفسه.

إعداد staging يفعّل OTP في التطبيق. إعداد الإنتاج المرشح يتطلب OTP أيضًا ويعطل تجاوز التحقق، لكنه لا يفعّل أسرار السحابة بمجرد بناء التطبيق. حالة الإطلاق الحالية موثقة في `production-readiness-20261020.md`.
