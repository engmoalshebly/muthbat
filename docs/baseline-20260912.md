# خط الأساس — 2026-09-12

هذه نتيجة المرحلة صفر على Ubuntu 24.04. لا تشمل بناء APK؛ يبني صاحب المشروع
نسخة Android النهائية على جهازه المحلي بعد تمرير إعدادات البيئة والتوقيع.

## الأدوات

- Flutter 3.47.4 / Dart 3.13.3
- Node.js 24.21.0 / npm 11.19.0
- Supabase CLI 2.117.0
- Deno 2.9.6
- Docker Engine 29.6.0

## بوابات التحقق

- `flutter analyze --no-fatal-infos`: بلا أخطاء أو تحذيرات بعد إصلاح التحذير الوحيد؛ تبقى ملاحظات lint غير حاجبة.
- `flutter test`: نجح 36 اختباراً.
- `npm test -- --runInBand` داخل `OpenWA`: نجح 110 اختبارات ضمن 8 مجموعات.
- `npm run build` داخل `OpenWA`: نجح.
- `npm run dashboard:build` داخل `OpenWA`: نجح.
- `supabase db reset --yes`: نجح تطبيق جميع الترحيلات من الصفر.
- `supabase db lint --local`: لا أخطاء أو تحذيرات في المخطط.
- `supabase test db`: نجح 133 اختباراً ضمن 11 ملفاً.

## إصلاحات ظهرت أثناء التحقق

- إصلاح محدد نهاية دالة SQL في ترحيل تصنيفات الدفتر المحلي، والذي كان يمنع تطبيق آخر ترحيل من الصفر.
- جعل قيم JSONB الابتدائية صريحة وتنظيف متغيرين غير مستخدمين حتى يمر فحص المخطط بلا ملاحظات.
- تحديث تعليقات المصادقة الحية لتصف مسار Supabase Edge Functions وOpenWA الفعلي بدل مسار Twilio القديم.
- اعتماد نسخة التطبيق `0.2.0+2` بوصفها نسخة ما قبل الإطلاق العام.

## ملاحظات غير حاجبة

- npm يبلغ عن تبعيات انتقالية قديمة أثناء التثبيت؛ لم تمنع الاختبار أو البناء، وتحتاج مراجعة اعتماد مستقلة قبل الإنتاج.
- بوابة `deno test --allow-env supabase/functions/` الحالية تفشل برسالة `No test modules found` لأن المستودع لا يحتوي اختبارات وحدة لـEdge Functions بعد. هذا خارج أوامر قبول المرحلة صفر، لكنه يعني أن مهمة `edge-unit` في CI ليست خضراء بعد.
- لم يُشغّل بناء APK أو مهمة `flutter-build` بناءً على قرار صاحب المشروع أن يتم البناء على جهازه المحلي.
- ملفات الخطط والتقارير التاريخية التي تذكر Twilio بقيت كسجل لقرارات سابقة، وليست وصفاً للتنفيذ الحالي.
